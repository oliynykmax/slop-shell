# AGENTS.md

## What this is
`slop-shell` — a fully hallucinated Unix shell. Every response is generated by an LLM; nothing is actually executed. Single Go module, `package main`, three source files.

## Commands
- Build: `go build -o slop-shell .`
- Run all tests: `go test ./...` (only `colorize_test.go` exists)
- Format: `gofmt -w .` — no project formatter/linter config, defaults apply
- No Makefile, no task runner, no CI workflows (`.github/` is absent)

## Runtime requirements
- `DEEPSEEK_API_KEY` must be set (env var or `.env` in CWD / `~/.config/slop-shell/.env`). `GEMINI_API_KEY` is a legacy fallback. The binary exits 1 if neither is set.
- Go toolchain must match `go 1.26.4` (see `go.mod`).

## Architecture (3 files, all `package main`)
- `main.go` — readline loop, MOTD, sudo handling, tab-completion wiring, `SlopShell` orchestration, system-prompt construction, anti-injection wrapper on user input.
- `provider.go` — `Provider` interface + `DeepSeek` implementation. Retry/backoff on 429/503, SSE streaming parser, `Probe` validates each model at startup, `selectModel` picks the first responding model.
- `colorize.go` — local regex-based ANSI colorizer applied to streamed output. The model is told not to emit ANSI codes; the colorizer adds them client-side.
- `colorize_test.go` — only test file. Covers colorizer, prompt-line detector (NBSP/tab edge cases), and the tab-completion LRU.

## Hardcoded values to watch
- **Hostname `slopbox`** appears in multiple places that must be kept in sync if renamed: `buildSystemPrompt` (system prompt), `trailingPromptRe` (main.go), `promptRe` and prompt checks (colorize.go), `isPromptLine` (main.go), and the initial `fmt.Sprintf("%s@slopbox:~$ ", user)` prompt. The colorizer and the model both key off `@slopbox:`.
- **Model list** is hardcoded in `DeepSeek.Models()`. Each is probed before the shell starts; the first to respond wins.
- **MOTD** is generated by `generateMOTD` in `main.go` — the demo block in `README.md` is illustrative and tends to drift from the code. Treat the source as truth.

## Conventions that differ from Go defaults
- The latest user message is wrapped with a `SYSTEM OVERRIDE` anti-injection string in `SlopShell.chat` before being sent. If you change prompt-handling code, preserve this.
- Session history is capped at 256 messages and re-sent every turn (`main.go` ~line 139). Not a token-budget concern — DeepSeek V4 has ~1M context.
- `~/.slop_history` is the persistent readline history file; falls back to `/tmp` only if `$HOME` is unset.
- Tab-completion uses the LLM with a 10s timeout and a 64-entry LRU cache (`completionCache`). Edit `aiCompleter.Do` if changing completion behavior.
- `s.buildSystemPrompt` instructs the model to behave as a Linux shell, hostname `slopbox`, starting cwd `/home/$USER`. The system prompt and the readline prompt are separate strings; the prompt is updated dynamically from the model's trailing `user@slopbox:cwd$ ` output via `trailingPromptRe`.
- Streaming prints line-by-line through the colorizer; the model's trailing prompt line is suppressed (detected by `isPromptLine` / `promptRe`).

## Editing tips
- `main.go` is the only file that touches the shell state, the system prompt, sudo, the MOTD, and the readline loop — expect a lot in this one file.
- Provider is interface-based; a new backend only needs to satisfy `Provider` in `provider.go` and be wired into `main()`.
- Don't add CI/lint config without checking with the user — the repo deliberately has none.
